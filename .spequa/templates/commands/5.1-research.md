## User Input

```text
$ARGUMENTS
```

You **MUST** consider the user input before proceeding (if not empty).

## Pipeline Position

```text
5-plan → 5.1-research (optional tool call) → 5-plan (refined) → 6-tasks
```

This command is an **optional ancillary** invoked from within `/spequa.5-plan` (or manually after an initial plan draft) when the plan contains unresolved technical questions, candidate library choices that need validation, or architecture decisions requiring evidence beyond what the spec provides.

Its output — `research.md` in the feature directory — feeds directly back into `5-plan` as sourced input, letting the agent finalize technology choices with documented rationale.

## When to Invoke

Invoke `5.1-research` when the plan contains any of:

- `[NEEDS RESEARCH]` markers (analog of `[NEEDS CLARIFICATION]` for technical unknowns)
- Candidate library choices requiring comparison (e.g., "WebSocket vs SSE", "Postgres vs SQLite")
- Performance assumptions that need benchmark data to validate
- Security implications of a chosen pattern that need documented analysis
- Compatibility checks across dependency versions or runtime environments
- Organizational-constraint lookups (internal standards, compliance requirements)

Skip when the plan is a straightforward application of known patterns with no open technical questions.

## Execution Steps

### 1. Read the draft plan

Load `specs/NNN-feature/plan.md` and scan for:

- `[NEEDS RESEARCH]` markers
- "Candidate libraries" or "Technology alternatives" sections
- Assumptions flagged with `?` or `TBD`
- Decisions marked as "provisional" or "pending validation"

If no research triggers are found, exit with status `NO_RESEARCH_NEEDED` and return to `5-plan` for finalization.

### 2. Extract research questions

For each trigger, formulate a concrete, answerable research question. Examples:

- "For real-time event delivery with 10k concurrent connections, is WebSocket or SSE a better fit given the project's existing Redis dependency?"
- "Does `library-xyz` v2.4+ have known CVEs that affect this use case?"
- "What is the p95 latency benchmark for `postgres-driver` vs `sqlx` on 1M-row inserts?"

### 3. Run research

Use the appropriate research mechanism (in priority order):

1. **Internal knowledge base** — check `.spequa/memory/` and `docs/` for prior decisions
2. **Code search** — look for existing patterns in the Equa codebase (how is this solved elsewhere?)
3. **Library documentation** — fetch official docs for candidate libraries
4. **Web research** — benchmarks, comparison articles, security advisories (use WebSearch/WebFetch)
5. **External tooling** — package registries, CVE databases, performance benchmarks

### 4. Synthesize findings

For each research question, produce a structured entry:

```markdown
## Q: <question>

**Answer**: <one-sentence recommendation>

**Evidence**:
- <source 1 with citation>
- <source 2 with citation>

**Trade-offs**:
- Option A: <pros/cons>
- Option B: <pros/cons>

**Decision**: <chosen option and why>

**Risks / open items**: <what we still don't know>
```

### 5. Write `research.md`

Append findings to `specs/NNN-feature/research.md` (create if missing). Preserve any existing content — research is additive.

### 6. Update the plan

Return to `/spequa.5-plan` with `research.md` as new input. The plan should now:

- Remove all `[NEEDS RESEARCH]` markers
- Lock in library/technology choices with "See research.md Q-N" citations
- Document rejected alternatives in the Complexity Tracking table

## Output

- `specs/NNN-feature/research.md` — structured Q&A with evidence and decisions
- Exit status signals for the pipeline orchestrator:
  - `RESEARCH_COMPLETE` — plan can be finalized
  - `RESEARCH_BLOCKED` — questions require human input (escalate to 4.1-expert-decision)

## Invocation Modes

- **Automatic** (from `0-pipeline`): Orchestrator scans plan.md for `[NEEDS RESEARCH]` markers after `5-plan` runs; invokes `5.1-research` if any found; returns to `5-plan` for finalization.
- **Manual**: User runs `/spequa.5.1-research "question text"` to investigate a specific concern outside the pipeline.
- **Escalation**: `5.1-research` can escalate to `4.1-expert-decision` when research surfaces options of roughly equal merit that require domain-expert judgment.
