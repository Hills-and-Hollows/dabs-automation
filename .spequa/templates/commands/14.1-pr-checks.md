## User Input

```text
$ARGUMENTS
```

You **MUST** consider the user input before proceeding (if not empty).

## Pipeline Position

```text
14-create-pull-request → 14.1-pr-checks (wait + verify) → 15-comet-review → 16-close
```

This command runs **automatically after `14-create-pull-request`** and **blocks progression to `15-comet-review`** until CI pipeline checks resolve. It converts the typical "push PR and hope CI passes" loop into an explicit pipeline phase with structured status reporting and actionable failure surfacing.

## When to Invoke

Always invoke after `14-create-pull-request` when:

- The repo has CI configured (GitHub Actions, CircleCI, Jenkins, etc.)
- The PR triggers automated checks (lint, test, build, security scan, coverage)
- Progression to browser-based review (`15-comet-review`) should wait for CI signal

Skip when:

- The repo has no CI
- The PR is marked `[skip ci]` or draft
- User explicitly overrides with `--no-wait` flag

## Execution Steps

### 1. Identify the PR

Read `.spequa/.pipeline-state.json` or parse the last `14-create-pull-request` output for:

- PR number and URL
- Target branch (usually `main`)
- Head branch (current feature branch)

Abort with error if no PR info is available.

### 2. Enumerate expected checks

Query GitHub (or CI provider) for the list of checks triggered by the PR:

```bash
gh pr checks <PR_NUMBER> --json name,status,conclusion,detailsUrl
```

Expected categories (Equa projects):

- **Lint**: ruff (Python), markdownlint, eslint (TS/JS)
- **Test**: pytest across Python 3.11/3.12/3.13, jest/vitest for frontend
- **Build**: package build, docker image build
- **Security**: GitGuardian, Snyk, CodeQL
- **Coverage**: codecov thresholds

### 3. Poll until resolution

Wait for all checks to reach a terminal state (`success`, `failure`, `cancelled`, `timed_out`, `neutral`, `skipped`). Recommended polling:

- Initial wait: 30 seconds (CI startup lag)
- Poll interval: 30 seconds
- Max wait: 20 minutes (configurable via `--timeout`)

While polling, emit progress updates every 60 seconds:

```text
[14.1-pr-checks] 3/7 checks complete — waiting on: build, test-py312, security-scan
```

### 4. Summarize outcomes

Once all checks resolve, produce a structured summary:

```markdown
## CI Check Summary — PR #<N>

| Check | Status | Duration |
|-------|--------|----------|
| lint-ruff | ✓ success | 12s |
| test-py311 | ✓ success | 1m 34s |
| test-py312 | ✗ failure | 1m 18s |
| build | ✓ success | 45s |
| security-scan | ✓ success | 22s |

**Overall**: FAILURE (1/5 failing)
**Blocker**: test-py312 — see details below
```

### 5. Surface actionable failures

For each failed check, extract and display:

- The specific failing test name or lint rule
- The error message (trimmed to ~10 lines)
- A direct URL to the CI log
- A suggested fix action (loop back to 10-implement, re-run lint, etc.)

Example:

```markdown
### ✗ test-py312

**Failing test**: `tests/test_package_distribution.py::test_migrate_preserves_user_files`
**Error**: `AssertionError: expected 3 files, got 2`
**Log**: https://github.com/EQUAStart/spequa/actions/runs/12345
**Suggested action**: loop back to `/spequa.10-implement` to fix the migration preservation logic
```

### 6. Gate the pipeline

- **All checks pass** → emit status `CHECKS_GREEN` and allow `15-comet-review` to proceed
- **Any check fails** → emit status `CHECKS_RED` and halt the pipeline
- **Timeout reached** → emit status `CHECKS_TIMEOUT` and require human intervention

### 7. Update PR metadata

Post a summary comment on the PR with the check results and link to the full report. If `CHECKS_RED`, also:

- Request changes on the PR (from the bot user)
- Tag the PR author with the actionable failure list

## Output

- `specs/NNN-feature/ci-report-PR<N>.md` — full structured CI check report
- Exit status signals for the pipeline orchestrator:
  - `CHECKS_GREEN` — all checks passed, advance to 15-comet-review
  - `CHECKS_RED` — failures found, halt pipeline, require fixes
  - `CHECKS_TIMEOUT` — CI didn't complete in time, escalate

## Invocation Modes

- **Automatic** (from `0-pipeline`): Orchestrator always invokes after `14-create-pull-request` succeeds.
- **Manual**: User runs `/spequa.14.1-pr-checks <PR_NUMBER>` to re-check an existing PR.
- **Re-run after fix**: After a `CHECKS_RED` result triggers a fix loop through `10-implement → 14`, this command re-runs automatically on the new commit.

## Configuration

Via `.spequa/config.yml`:

```yaml
pr_checks:
  timeout_minutes: 20
  poll_interval_seconds: 30
  required_checks:
    - lint-ruff
    - test-py311
    - test-py312
    - test-py313
  allow_neutral: true    # treat 'neutral' conclusion as pass
  skip_drafts: true      # don't wait for checks on draft PRs
```
